# Для Claude Code: две страницы подрядчиков

Продолжаем существующий путь: организатор создал свадьбу, выбрал задачи, теперь выбирает подрядчиков. Реализуй **только две страницы ниже** в текущем стиле сервиса. Не переделывай создание свадьбы и задачи.

## 1. «Мои подрядчики» — личная база пользователя

Добавь отдельный доступный из меню раздел **«Мои подрядчики»**. Здесь каждый вошедший пользователь хранит **только собственных** подрядчиков. Это не общая база сервиса и не общая база агентства: даже два сотрудника одной команды видят разные списки. Список сохраняется между входами пользователя и может использоваться в разных его свадьбах.

На странице: поиск по имени и категории, список карточек и кнопка «Добавить подрядчика». Для записи нужны **категория**, **имя/название**, необязательные **телефон**, **ссылка/соцсеть** и **заметка**. Пользователь может добавить, изменить и удалить свою запись; удалить чужую нельзя. Категории первого MVP: ведущий, декоратор, фотограф, видеограф, флорист, стилист, визажист, кейтеринг, музыка/DJ, кондитер, другое. В категории может быть сколько угодно имён.

Если база пуста, покажи «Добавьте первого подрядчика», без выдуманных контактов. При удалении личной записи уже выбранный подрядчик **остаётся в свадьбе**: связь с проектом не должна исчезать неожиданно.

## 2. «Подрядчики» внутри свадьбы

На странице конкретной свадьбы добавь раздел **«Подрядчики»** и кнопку **«+ Выбрать подрядчиков»**. Кнопка открывает выдвижную панель: категории, например «Ведущий», раскрываются в списки имён **из личной базы текущего пользователя**. Организатор отмечает нужные имена чекбоксами и нажимает «Добавить N». Можно выбрать несколько человек одной категории; это кандидаты, не автоматически «подтверждённые» подрядчики.

В панели есть «Добавить нового подрядчика», если нужного имени нет. Новая запись сохраняется в личную базу текущего пользователя и сразу становится доступной для выбора. До нажатия «Добавить N» проект не меняется.

После сохранения выбранные люди появляются **только у этой свадьбы**: группировка по категориям, имя, контакты при наличии, отметка «Кандидат». Для каждого можно поставить «Подтверждён», вернуть в кандидаты или убрать из свадьбы. Удаление из свадьбы **не удаляет** его из личной базы. Уже добавленные в эту свадьбу люди помечены в панели и повторно не создаются. Подрядчики других свадеб сюда не попадают.

**Граница приватности:** личный список одного пользователя никогда не показывать другому пользователю и не отдавать его данные по прямому запросу. Когда пользователь добавляет конкретного подрядчика в свадьбу, в проект попадает копия выбранных данных этой записи; участники с доступом к свадьбе видят именно её. Остальная личная база остаётся закрытой. Изменение личной записи позже не должно молча менять уже сохранённые контакты в чужой или общей карточке проекта. Проверки принадлежности личной записи и доступа к свадьбе делать на сервере, не только скрытием кнопок.

## Проверка

Создай у пользователя А двух ведущих и декоратора, у пользователя Б — своего ведущего. В личной базе каждого видны только его записи. В свадьбе пользователь А выбирает ведущего и декоратора: оба появляются в разделе свадьбы после сохранения, а остальные контакты его базы недоступны пользователю Б. Повторное добавление не создаёт копий. Удаление подрядчика из свадьбы сохраняет его в базе; удаление из личной базы не убирает его из уже заполненной свадьбы. Проверить desktop и mobile.
