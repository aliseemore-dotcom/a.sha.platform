# Передача: «Мои мероприятия» и обзор мероприятия

Спецификации: [`specs/01-events.md`](specs/01-events.md), [`specs/01-events-iteration-2.md`](specs/01-events-iteration-2.md),
[`specs/01-events-iteration-3.md`](specs/01-events-iteration-3.md) (объединяет части I и II — поведение и визуальную
доработку экрана «Мои мероприятия» — и заменяет отдельные файлы итераций 2–3; где документы расходятся, действует
итерация 3) и [`specs/02-overview.md`](specs/02-overview.md) (обзор конкретного проекта).

## Обзор мероприятия (specs/02-overview.md) — недостающие поля и решения

По разделу 7 спецификации: если схема не содержит нужного поля, это нужно назвать явно, а не
подменять данные угадыванием по названию задачи.

**Недостающее поле, которое пришлось добавить:** `waitingFrom` (кого/что ждём — площадку,
подрядчика, пару) на задаче. Без него строка «Ждём ответа» не могла бы показывать «от кого» из
раздела 1.5. Добавлено как обычное необязательное поле задачи, попадает в контракт `GET /api/events/:id`.

**Поле, которое сознательно не стали вводить:** момент, с которого длится ожидание («с какого
момента ждём» — отдельно от контрольной даты). У задачи есть только `updatedAt` (общая метка
последнего изменения) — использовать её как «с какого момента ждём» значило бы угадывать: `updatedAt`
меняется по любой причине, не только при переходе в `waiting`. Строка «Ждём ответа» показывает
только то, что действительно хранится: чего ждём, от кого (если есть `waitingFrom`), кто отвечает
внутри команды, контрольная дата (если есть `followUpAt`). Если понадобится честное «с какого
момента» — нужно отдельное поле, проставляемое в момент перехода в `waiting`.

**Не реализовано умышленно, а не забыто:**
- *Редактирование базовых данных проекта* — в спецификации упомянуто как пункт меню (раздел 1.1),
  но её собственное поведение (какие поля, валидация, кто может) нигде не описано. Показывать
  пункт меню, который ничего не делает, запрещено самой спецификацией («не создавать видимость
  интеграции… если они ещё не реализованы»), поэтому в меню остался только архив/восстановление.
- *«+ Добавить задачу»* (раздел 1.6) — по тексту документа доступно «только там, где реально
  реализовано». Создания произвольных задач в API нет (есть только стартовый план и отметка
  «выполнено»), поэтому кнопки нет.
- *Фото обложки* — путь отрисовки поддержан (`event.coverUrl` → `<img class="overview-cover">`),
  но в демо-данных фото нет ни у одного проекта: загрузки фото в продукте не существует, а
  подставлять стоковое изображение бренд-бук прямо запрещает.

**Решения там, где документ оставляет выбор:**

| Пункт | Как сделано |
|---|---|
| Общие компоненты с «Мои мероприятия» | Строка задачи — общий `taskRow()`; «Требует решения» использует ту же функцию срочности (`buildAttention`/`classifyTask`) через `GET /api/events/:id`, поэтому число здесь и на списке никогда не расходится |
| «3–5 строк в зависимости от места» | Тот же лимит, что на «Мои мероприятия»: 3 на телефоне, 5 шире (`web/js/breakpoints.js`, общий модуль) |
| Раскрытие «Требует решения» | Список одного проекта обычно небольшой, поэтому «Показать все N» разворачивает уже загруженные данные на клиенте — без отдельной пагинации, в отличие от глобального списка |
| «Сейчас в работе» / «Ждём ответа» | Полный список `in_progress` / `waiting` без верхнего предела на количество — это рабочий, а не декоративный блок |
| «Все задачи» | Превью ≤5 (приоритет: сначала попавшие в «Требует решения», затем в работе, затем ожидание, затем остальное, по ближайшему сроку) со ссылкой-якорем `#all-tasks` на полный список ниже на той же странице — отдельной страницы задач ещё нет |
| Сохранение состояния списка при возврате | Ссылки на карточки и на глобальные строки внимания несут `?from=<путь списка>`; «← Мои мероприятия» использует его, если он есть и указывает на `/events…`, иначе — обычный список |
| Порядок «В работе» | Ближайший срок → `updatedAt` по убыванию (тот же порядок, что и в превью карточки списка) |

## «Мои мероприятия», итерация 3 — решения и отступления

| Пункт | Как сделано |
|---|---|
| «Нужно напомнить» | Убран из сигналов внимания по прямому уточнению документа: у `waiting`/`followUpAt` нет подтверждённого источника и правила наступления/снятия. Поле `followUpAt` осталось на задаче на будущее, но не участвует в `classifyTask`. Статус `waiting` по-прежнему виден в списке задач проекта («Ждём ответа») |
| Компактные статусы (часть II §1) | `.chip`: 11px/14px до 768px, 12/16 шире; паддинги 3/8; форма-иконка 10px, зазор 4px. Детальная панель задачи — модификатор `chip--detail` (12px, паддинг 4/8). Интерактивная цель строки внимания не уменьшилась (44–56 px), сократилась только декоративная плашка |
| Голубой блок внимания (§2) | Токены `--attention-*` взяты из документа как прототип, применены только к `.attention` на экране списка; светлый вариант внутри обзора проекта (`.attention__list--light`) и остальная шапка/кнопки не тронуты |
| Контуры карточек (§3) | Сплошная красная рамка вокруг всей карточки убрана — срочность видна из плашки «Срочно · N» и точки рядом с ней. Обычная граница — `--card-border` (#E4E8EA), тень только на hover. Внутренняя плашка срочности мягче (`--urgent-tint-soft`) |
| «Закрыть задачу» → «Вернуться к проекту» | Сделано (связь с предыдущей проверкой) |
| «Переместить в архив» в меню проекта | Вынесено в меню действий (⋮ рядом с заголовком), а не отдельной кнопкой в шапке обзора |

## «Мои мероприятия», итерация 2 — решения и отступления

| Пункт | Как сделано |
|---|---|
| Приоритет причины | `blocked → overdue → due_today`; заблокированная и просроченная задача — одна строка «Заблокировано». Сортировка: заблокированные и просроченные одной группой выше «Сегодня», старший срок выше, без срока — в конце группы, затем `eventId`, `taskId` |
| Метки срока | «Сегодня · HH:mm»; прошедший сегодня срок — «Просрочено с HH:mm»; раньше — «Просрочено N дней» по календарным дням пространства; срок-дата истекает в конце дня |
| «Показать все N» | N — общее число сигналов («Показать все 7», как в критерии приёмки 2). В тексте раздела 3.2 N назван числом скрытых строк — противоречие; выбран вариант критерия |
| Раскрытый список | Грузится с сервера страницами по 20, «Показать ещё» — следующая страница, «Свернуть» — обратно к 5/3 строкам |
| Сортировка «По дате» | Будущие (включая сегодня) по возрастанию → прошедшие, **сначала недавние** (порядок внутри группы в ТЗ не задан) → без даты; затем название и `id` |
| Архив | Один порядок: по дате события, сначала поздние; выбор сортировки скрыт и заменён подписью |
| Стадии | «В подготовке» / «Завершение проекта» / «В архиве» — только подписи, сохранённый `lifecycle` не меняется |
| Переход по сигналу | `/events/:id/tasks/:taskId` — обзор проекта с панелью задачи; работает после обновления и в новой вкладке. Нет задачи — «Задача больше недоступна» и ссылки на проект и список; нет доступа к проекту — «Проект не найден или доступ к нему закрыт» |
| Выполнение задачи | В панели задачи — «Отметить выполненной» (`POST /api/events/:id/tasks/:taskId/complete`); счётчики и карточки пересчитываются из того же снимка |
| Шапка | На ширине < 600 px название агентства уходит в меню профиля; «Выйти» — в меню |
| Кому показывать внимание | Все доступные активные проекты агентства (раздел 8). Фильтр «Мои / Команды» — когда появится распределение нагрузки |

Сопоставление полей модели с ТЗ: `eventType` → `kind`, `venue` → `locationName`, `lifecycleStatus` → `lifecycle`,
`coverImage` → `coverUrl`, `projectId` → `eventId`, `assignee` → `assigneeId`, `blockedReason`, `waitingFrom` — добавлены.

## Сделано

- Маршруты `/events`, `/events/:id/overview`, `/events/:id/tasks/:taskId`; без сессии — переход на вход
  с безопасным `returnTo`.
- Серверный список: вкладки с счётчиками до поиска, поиск по названию и месту (регистр, ё/е),
  сортировки «По дате» и «По вниманию», пагинация по 20 курсором.
- «Требует внимания»/«Требует решения»: `blocked → overdue → due_today`, один объект — один раз;
  сроки с точностью `dueAt` (со временем) или `dueDate` (день; просрочен со следующего дня в поясе пространства).
  5 строк на компьютере / 3 на телефоне, «Показать все N» раскрывает.
- Карточка: дата или «Дата уточняется», место, состояние, один срочный повод, до двух «В работе»,
  «Открыть проект»; «Дата прошла · проект активен» без отрицательного отсчёта.
- Обзор проекта: шапка со стадией и «через N дней», три счётчика-перехода, «Требует решения»,
  «В работе», «Ждём ответа», превью «Ближайшие задачи» и полный список «Все задачи», меню
  архивирования, панель одной задачи с «Отметить выполненной».
- Создание: диалог с проверкой полей, `idempotencyKey`, стартовый план `wedding_v1`
  с уникальностью `(eventId, templateKey)`, `planStatus` и «Повторить создание плана».
- Архив и возврат из архива (owner). Удаления нет.
- Состояния: скелетоны, ошибки с «Повторить», пустые состояния, «Нет соединения».
- Автообновление: при возврате фокуса, по таймеру `refreshAt`, после создания/восстановления/выполнения задачи.
- Шрифт Involve (8 начертаний, woff2, `font-display: swap`) и лицензия OFL — `web/fonts/`.
- Проверено в Chromium на 375 и 1440 px без горизонтальной прокрутки, включая длинные названия и площадки.

## Не готово — не выдавать за продукт

| Что | Состояние |
|---|---|
| Вход | Системы авторизации нет. Стенд использует выбор демо-пользователя; при `DEMO=0` войти нельзя |
| Хранилище | В памяти процесса, данные теряются при перезапуске. Нужна БД; интерфейс — `server/store.js` |
| Часовой пояс | Настройки пространства нет. Стенд — `Europe/Moscow`; вне стенда — пояс устройства из `X-Time-Zone` |
| Редактирование проекта | Нет ни в API, ни в интерфейсе — пункт меню сознательно не добавлен (см. выше) |
| Добавление задачи вручную | Нет ни в API, ни в интерфейсе |
| Обложки | Загрузки фото нет; путь отрисовки поддержан (`coverUrl`), но не проверен на реальном фото |
| «С какого момента ждём» | Не хранится отдельно от контрольной даты (`followUpAt`) — см. раздел выше |

## Нужно от заказчика

1. **Название продукта и логотип.** В шапке сейчас только название рабочего пространства.
2. **Библиотека иконок** (Lucide — «предложено к утверждению»). Сейчас иконок нет, формы статусов — CSS.
3. **Поведение редактирования проекта и добавления задачи** — какие поля, кто может, — чтобы включить
   эти пункты в меню и в «Все задачи» по-настоящему, а не заглушками.
