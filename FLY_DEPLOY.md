# Деплой пилота на Fly.io

Бесплатная альтернатива Render на время тестирования: постоянный диск и
работающий вход по паролю без ежемесячной платы за диск. Выполняется в
обычном терминале на вашем компьютере — не здесь, у сессии нет доступа
к api.fly.io.

## 0. Один раз: аккаунт и CLI

1. Зарегистрируйтесь на https://fly.io (нужна карта для подтверждения
   личности — деньги с неё не списываются, пока не выйдете за бесплатный
   лимит).
2. Поставьте CLI:
   - macOS/Linux: `curl -L https://fly.io/install.sh | sh`
   - Windows (PowerShell): `pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"`
3. `fly auth login` — откроется браузer, войдите тем же аккаунтом.

## 1. Клонируйте репозиторий и выберите имя приложения

```bash
git clone https://github.com/aliseemore-dotcom/a.sha.platform
cd a.sha.platform
git checkout claude/count-create-documents-41di1x   # или main, если ветку уже смержили
```

В репозитории уже лежат `Dockerfile` и `fly.toml` — шаблон нужно
подправить под себя:

1. Откройте `fly.toml`, замените `app = "amore-pilot"` на своё уникальное
   имя (например, `app = "amore-ivanova-pilot"` — Fly проверит уникальность
   при запуске).
2. Там же замените `PUBLIC_URL` на `https://<ваше-имя>.fly.dev` — домен
   Fly выдаёт по имени приложения ещё до деплоя, поэтому его можно
   прописать заранее.
3. `primary_region = "fra"` (Франкфурт) — ближайший к России регион Fly;
   список остальных — `fly platform regions`, можно оставить как есть.

## 2. Создайте приложение и постоянный диск

```bash
fly apps create <ваше-имя>       # то же имя, что в fly.toml
fly volumes create data --app <ваше-имя> --region fra --size 1
```

`--size 1` — 1 ГБ, для текста задач/смет/подрядчиков этого хватит надолго;
можно увеличить позже командой `fly volumes extend`.

## 3. Деплой

```bash
fly deploy
```

Соберёт `Dockerfile` (без npm-зависимостей — сборка быстрая) и выложит
на `https://<ваше-имя>.fly.dev`. Откройте адрес — должен появиться экран
входа (без выбора демо-пользователя: это уже боевой режим `DEMO=0`).

## 4. Создайте пространство и владельца

Через SSH-консоль внутри контейнера — та же роль, что Render Shell:

```bash
fly ssh console --app <ваше-имя>
npm run admin -- create-workspace --name "Название агентства" \
  --owner-email you@example.com --owner-name "Ваше имя" --time-zone Europe/Moscow
exit
```

Команда напечатает одноразовую ссылку вида `https://<ваше-имя>.fly.dev/invite/...`
— откройте её в браузере, задайте пароль и войдите. Дальше через
«Команда» в меню профиля приглашайте коллег теми же ссылками.

## 5. Дальнейшие деплои

После каждого обновления кода — снова `fly deploy` из папки репозитория.
Данные на диске `data` не трогаются: свадьбы, подрядчики, смета остаются.

## Проверка, что всё по-настоящему сохраняется

1. Создайте тестовую свадьбу с одной задачей.
2. `fly deploy` ещё раз (без изменений в коде — просто повторный деплой)
   или `fly machine restart <id>` (id — из `fly status`).
3. Обновите страницу — свадьба и задача должны остаться.

## Резервные копии

Сервер сам копирует базу раз в сутки в `/data/backups` на том же диске
(команда `backup-now` — вручную: `fly ssh console` → `npm run admin -- backup-now`).
Это не защищает от потери самого диска — на время тестирования можно
этим ограничиться, для боевого использования стоит подключить внешнее
хранилище (`BACKUP_S3_*`, см. README) или периодически скачивать копию:

```bash
fly ssh sftp get /data/backups/<имя-файла>.db ./backup.db --app <ваше-имя>
```

## Деньги

`shared-cpu-1x` / 256 МБ и 1 ГБ диска в `fly.toml` — минимальная
конфигурация, укладывается в бесплатный ежемесячный лимит Fly почти
при любой нагрузке пилота. `auto_stop_machines = true` — машина
останавливается при простое и запускается заново по первому запросу
(несколько секунд задержки на «холодный старт»), чтобы не расходовать
лимит вхолостую. Точные условия бесплатного лимита у Fly меняются —
проверьте актуальные цифры на https://fly.io/docs/about/pricing/ перед
тем как звать в пилот больше 2–3 человек.
